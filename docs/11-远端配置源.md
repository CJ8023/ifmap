# 11 · 远端配置源（`ifmap-provider-remote`）

> 适用版本：`0.1.0-SNAPSHOT`　作者：caijun

本文覆盖 `ifmap-provider-remote` 模块：**配置不在本地库、而在另一个服务的 HTTP 接口里**时，
如何把它接成 `ConfigRepository`。

典型场景有两种：

| 场景 | 说明 |
| --- | --- |
| 存量系统已有「配置中心接口」 | 例如 ECC 的 `IBankintConfigApi`（`query_bankint_config_list` / `query_logic_branch_list` / `insert_log`）。**一行表都不用迁**就能先跑起来 |
| 配置由别的服务统管 | 配置服务是唯一写入方，ifmap 只读；执行日志也回写给它（或另接一个日志 sink，见 [`docs/05`](05-SpringBoot集成.md) §3.5） |

> 与 [`docs/04`](04-接入与建表.md) 的 JDBC 仓储是**并列关系**：两者都实现同一个 `ConfigRepository`，
> 选一个即可（也可以自己再实现一个）。引擎、模板、规则、分支、动作这些**完全不感知**配置来自哪里。

---

## 1. 为什么不是「直接依赖 Feign」

本模块**不**依赖 Spring Cloud OpenFeign，而是定义一个函数式 SPI `ConfigFetcher`，由宿主注入。
三条理由：

| 理由 | 说明 |
| --- | --- |
| 不把版本矩阵强加给宿主 | Spring Cloud 的版本必须与 Boot 大版本严格配对（且 Feign 在 2022 之后改过坐标与默认实现）。宿主本来就有自己的 Feign / RestTemplate，没必要让 ifmap 决定 |
| 鉴权与治理在宿主手里 | 内网调用常带自家 `ApiReq` 头透传、签名、超时、重试、熔断。这些逻辑宿主已经写好了，ifmap 再包一层只会打架 |
| 保持 Java 8 + 零 Spring 依赖 | 与 `ifmap-core` 同样的取舍：模块只有 `ifmap-provider-remote → ifmap-core` 一条依赖，纯 Java / Spring Boot 2 / 3 都能用 |

代价是宿主多写 10~20 行适配代码（见 §3）。换来的是「谁的 HTTP 客户端谁来配」。

## 2. 实现方约定（`ConfigFetcher`）

```java
public interface ConfigFetcher {

    /** GET：返回响应体原文；查不到返回 null 或空串。 */
    String get(String uri, Map<String, String> query);

    /** POST JSON：返回响应体原文。 */
    String postJson(String uri, String jsonBody);
}
```

实现时必须遵守：

| 约定 | 为什么 |
| --- | --- |
| 返回**响应体原文**（不要提前反序列化成 VO） | 映射与容错都在 `JsonConfigMapper` 里，换字段名不用改适配层 |
| 「查不到」返回 `null` / 空串 | 与「查到了但是空数组」等价，都按空列表处理 |
| **非 2xx、超时、连接失败必须抛异常** | 不许吞成空串：否则「远端挂了」会被当成「没有配置」，表现为业务静默不执行 |
| 不要在这里做重试与降级 | 重试策略属于宿主的 HTTP 客户端；ifmap 侧不做重试，避免超时被放大 |

> 空响应体、`"null"`、`"[]"`、元素为 `null`、非数组 JSON …… 各自的处理都在 §4 里写清了。
> 只有「非法 JSON」和「响应体不是数组」会抛 `IfmapConfigException`。

## 3. 三种接法

### 3.1 Spring Boot 3 + 已有 Feign 客户端

```java
@FeignClient(name = "financing-scheme", url = "${ecc.api.url}", configuration = EccFeignConfig.class)
public interface BankintConfigFeign {

    @GetMapping("/api/bankint/query_bankint_config_list")
    String queryConfigs(@RequestParam("interfaceNo") String interfaceNo,
                        @RequestParam(value = "busiNode", required = false) String busiNode);

    @GetMapping("/api/bankint/query_logic_branch_list")
    String queryBranches(@RequestParam("interfaceNo") String interfaceNo);

    @PostMapping(value = "/api/bankint/insert_log", consumes = MediaType.APPLICATION_JSON_VALUE)
    String insertLog(@RequestBody String body);
}
```

```java
@Configuration
class IfmapRemoteConfig {

    @Bean
    ConfigFetcher ifmapConfigFetcher(BankintConfigFeign feign) {
        return new ConfigFetcher() {
            @Override
            public String get(String uri, Map<String, String> query) {
                // 路径里只有两个查询参数，直接分派比解析 uri 更清楚
                return uri.endsWith("/query_logic_branch_list")
                        ? feign.queryBranches(query.get("interfaceNo"))
                        : feign.queryConfigs(query.get("interfaceNo"), query.get("busiNode"));
            }

            @Override
            public String postJson(String uri, String jsonBody) {
                return feign.insertLog(jsonBody);
            }
        };
    }

    @Bean
    ConfigRepository ifmapConfigRepository(ConfigFetcher fetcher, JsonOps jsonOps) {
        return new RemoteConfigRepository(fetcher, jsonOps);   // 默认 baseUri = /api/bankint
    }
}
```

> 声明 `ConfigRepository` bean 后，starter 的 `JdbcConfigRepository` 会自动让位（它的条件里有
> `@ConditionalOnMissingBean(ConfigRepository.class)`），**不需要排掉任何依赖**；此时建表也不再必要
> （把 `ifmap.ddl.auto` 设为 `false`）。如果宿主机连 `DataSource` bean 都没有，JDBC 仓储与自动建表
> 是**整个不装配**的 —— 纯远端（配置 + 日志都在远端）的部署不需要引任何数据库依赖。

### 3.2 Spring 5 / 纯 Java + `RestTemplate`

```java
RestTemplate restTemplate = new RestTemplate();
restTemplate.setUriTemplateHandler(new DefaultUriBuilderFactory("http://financing-scheme"));

ConfigFetcher fetcher = new ConfigFetcher() {
    @Override
    public String get(String uri, Map<String, String> query) {
        UriComponentsBuilder builder = UriComponentsBuilder.fromPath(uri);
        query.forEach(builder::queryParam);
        // RestTemplate 对 4xx/5xx 默认抛 HttpClientErrorException/HttpServerErrorException —— 正合约定
        return restTemplate.getForObject(builder.build().toUriString(), String.class);
    }

    @Override
    public String postJson(String uri, String jsonBody) {
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(MediaType.APPLICATION_JSON);
        return restTemplate.postForObject(uri, new HttpEntity<String>(jsonBody, headers), String.class);
    }
};

ConfigRepository repository = new RemoteConfigRepository(fetcher,
        new JacksonJsonOps(), "http://financing-scheme/api/bankint");
```

### 3.3 单测 / 本地开发

`ConfigFetcher` 只有一个接口两个方法，测试里用匿名类或 lambda 记录请求、返回预置报文即可
（`ifmap-provider-remote` 自己的 `RemoteConfigRepositoryTest` 就是这么做的），无需启动 HTTP 服务。

## 4. 映射规则（`JsonConfigMapper`）

远端返回的 JSON 数组 → `IfmapConfig` / `LogicBranchConfig`。规则如下：

| 项 | 行为 |
| --- | --- |
| **键名风格** | 归一化后匹配：去掉 `_` / `-` 再转小写。`interfaceNo`、`interface_no`、`INTERFACE-NO` 等价 |
| **未识别的键** | 直接忽略（远端可以自由加字段，不用同步改 ifmap） |
| **旧键名兼容** | `partnerCode` / `partnerName` 是改名后的键；存量报文里叫 `bankCode` / `bank_code` / `bankName` / `bank_name` 的**照样收**（**新键优先、旧键兜底**）。因此这次改名**不需要远端服务同步发版**；若新旧键同时出现，以新键为准 |
| **缺失的可选字段** | 按建表 DDL 的默认值补齐（与 JDBC 仓储读出来的对象逐字段一致）：`interface_order / version / del_status / deleted_seq → 0`、`status → 1`、`result_flag / success_value / strategy_name / remark → ''` |
| **必填字段** | 判定口径 = DDL 里 `NOT NULL` 且**没有** `DEFAULT` 的列。配置：`interface_no / interface_code / interface_name / busi_node / partner_code`；分支：`interface_no / logic_branch_name`。缺失或空白 → 抛异常并指明「第几条、缺哪个字段」 |
| **数字** | 容忍 JSON 数字与数字字符串（远端 VO 里 `keyId` / `interfaceOrder` 常是 `String`）；小数、非法串、超 `int` / `long` 范围 → 抛异常 |
| **时间** | 容忍 ISO-8601（`2026-01-02T03:04:05`）与常见库格式（`2026-01-02 03:04:05`，可带毫秒）；解析失败 → 抛异常 |
| **文本列** | 只接受字符串 / 数字 / 布尔（数字与布尔转文本）；**对象或数组 → 抛异常**（不允许出现 `{a=1}` 这种 Java `toString` 悄悄落库） |
| **租户** | **以调用方查询的租户为准**，远端报文里的 `tenantId` 键不参与（防远端串租）。`tenantId` 为空 → 单租户 `-1`；非数字 → 抛异常 |

两个容易配错的地方：

1. **`logic_branch_order` 缺失时按下标补齐（从 1 起）**，不是一律填 `0`。存量语义是「按返回顺序生效」，
   全填 `0` 会退化成「按主键兜底」，顺序可能变。远端返回的数组顺序就是分支顺序，**已删除的行也占位**
   （不会把后面的行提前）。
2. **`result_flag` / `success_value` 缺失 ≠ 判定失败**：前者按 DDL 默认值补成空串，语义是
   「没有约定字段 → 默认成功」（见 [`docs/06`](06-执行编排与策略扩展.md) §7）。

响应体形状的处理：

| 响应体 | 结果 |
| --- | --- |
| `null` / 空串 / 纯空白 | 空列表 |
| `"null"` / `"[]"` | 空列表 |
| JSON 数组（元素是对象） | 逐条映射 |
| 非数组（对象 / 数字 / 字符串） | `IfmapConfigException`（消息里带响应体前 200 字符） |
| 元素不是对象（如 `[1]`）或 `[null]` | `IfmapConfigException` |
| 非法 JSON | `IfmapConfigException` |

## 5. 读写的三个本地兜底

`RemoteConfigRepository` 在映射之后还会做三件事，都是有意的「不信任远端 SQL」：

| 兜底 | 说明 |
| --- | --- |
| **本地再筛一遍** | 配置只留 `del_status = 0`（或缺失）且 `status = 1`；分支只留 `del_status = 0`。远端条件被改动时，行为不会跟着漂 |
| **本地排序** | 配置按 `interface_order` 升序、同值按 `key_id`；分支按 `logic_branch_order` 升序、同值按 `key_id` —— 与 JDBC 实现的 `ORDER BY` 完全一致 |
| **空白查询条件不拼进查询串** | `busiNode` 为空时不传 `busiNode` 参数（远端若按 `busi_node = ''` 过滤会查不到数据） |

`saveExecutionLog` 通过 `POST {baseUri}/insert_log` 把脱敏后的日志 JSON 发给远端：

- 远端返回 `false`（JSON 布尔或字符串 `"false"`）→ 抛 `IfmapConfigException`（**不静默丢审计**）；
- 远端返回其它内容（含空体）→ 视为成功；
- 引擎侧写日志失败只降级为 `WARN`，**不影响业务结果**（见 [`docs/08`](08-日志与合规.md)）；
- 想写到另一个库、而不是回写远端？把 `ExecutionLogSink` 换成 JDBC 那个即可，见 [`docs/05`](05-SpringBoot集成.md) §3.5。

## 6. 与存量配置接口的差异（迁移前必读）

如果把存量系统的配置接口直接接上来，注意这几处**两边风格不同**的地方：

| 项 | 存量常见形态 | 本模块的处理 |
| --- | --- | --- |
| 路径 | `GET {SERVER_URI_API}/bankint/query_bankint_config_list` | 默认 `baseUri = /api/bankint`；与存量不一致时用三参构造器传实际前缀 |
| 返回结构 | 直接是 `List<BankintConfigVO>`（camelCase，`keyId` / `interfaceOrder` 是 `String`） | 数值容忍数字串；键名风格自动归一 |
| 缺列 | 不返回 `status` / `version` / `tenantId` / `delStatus` / 审计列 | 按 DDL 默认值补齐，不影响运行 |
| 分支顺序 | 不返回 `logicBranchOrder` | 按返回顺序（数组下标）补齐，保持「按返回顺序生效」 |
| 判定值写法 | `success_value` 支持 `!值` **取反** | **不支持**（ifmap 只支持 `,` / `;` 分隔的多值与忽略大小写），见 [`docs/10`](10-迁移指南.md) §7 |

最后一条是**最容易静默出错**的：`!0000` 在存量里是「不等于 0000 即成功」，在 ifmap 里会被当成一个字面候选值，
永远不会命中。迁移前先扫一遍 `success_value like '!%'` 的配置行。

## 7. 自测

```bash
# 本模块（映射规则、请求路径与参数、排序筛选、日志回写、端到端全链路）
mvn -pl ifmap-provider-remote -am test
```

模块测试全部用**假的 `ConfigFetcher`**（按 URI 返回预置报文），不起 HTTP 服务、不依赖 Docker；
端到端用例会把「远端配置 → 渲染 → 出网 → 判定 → 分支动作 → 脱敏日志回写远端」整条链跑一遍。
