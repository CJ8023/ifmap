# 逻辑分支判定统一为规格（`branch_judge`）实施计划

> **For agentic workers:** REQUIRED: 按任务顺序执行，每步先红后绿再提交。设计依据：[`../specs/2026-10-22-分支判定规格化-design.md`](../specs/2026-10-22-分支判定规格化-design.md)。步骤用 `- [ ]` 跟踪。

**Goal:** 把 `ifmap_logic_branch_config` 的 `logic_branch_flag` + `logic_branch_value` 两列换成单列 `branch_judge`，规格语法/解析器/失败语义与 `result_judge` 完全同源。

**Architecture:** 解析器复用（`ResultJudgeSpec` 加"允许算子集"参数 + 共享求值树）；分支专用两个无 path 叶子算子 `strategy`（走 `@LogicBranch` SPI）/`judged`（比 `result_judge` 的 actualValue）；编排层用 `BranchJudge`（带 LRU）替换 `matches()` 的两条隐藏通道；非法规格 fail-closed 到 `SPEC_INVALID`。

**Tech Stack:** Java 8 / Maven 多模块 / JUnit 5 / Jackson / Liquibase formatted SQL / H2 真库测试（`TestDatabases`）。

**构建纪律：** 所有 `mvn` 命令必须在**仓库根目录**执行（`cd /mnt/d/cj/code/ifmap`），不要用 `-f` 指 pom，否则 `${maven.multiModuleProjectDirectory}` 指错、`spotbugs-exclude.xml` 找不到。

**Files:**

- [ ] Step 1: `JudgeOp` 加算子
  ```java
  EQ, NE, IN, NOT_IN, EXISTS, NOT_BLANK, REGEX, ALWAYS,
  /** 分支专用：交 @LogicBranch 策略求值（无 path） */ STRATEGY,
  /** 分支专用：与 result_judge 的 actualValue 比较（无 path，值必须是数组） */ JUDGED;

  /** 是否需要 path（STRATEGY/JUDGED 直接读"别处的输入"，不读原文） */
  public boolean requiresPath() { return this != STRATEGY && this != JUDGED; }
  // requiresValue(): ... || this == STRATEGY
  // requiresValueList(): ... || this == JUDGED
  // matches(): case JUDGED -> actual != null && contains(getValues(), condition, actual);  // 归属语义
  //            case STRATEGY -> false;   // 由 BranchJudge 预处理，走到这里说明用错了
  ```
- [ ] Step 2: `BranchInputs`（新接口）
  ```java
  public interface BranchInputs {
      boolean strategyMatched(String key);
      String judgedValue();
  }
  ```
- [ ] Step 3: `ResultJudgeSpec` 参数化（公开 API 行为不变）
  - `static final Set<JudgeOp> RESULT_OPS`（8 个，含 ALWAYS）；`BRANCH_OPS` = RESULT_OPS + STRATEGY + JUDGED
  - `validate(spec, jsonOps)` → `validate(spec, jsonOps, RESULT_OPS)`；`parse` 同理
  - `parseNode/parseCondition` 多一个 `Set<JudgeOp> allowed` 形参：`op` 不在集合里 → `add(errors, path/op 的 op 非法/分支专用算子…)`，文案含「分支专用」/「result_judge 不支持」
  - `parseCondition`：`op.requiresPath()` 时不接受 path 缺失；`!requiresPath()` 时**拒绝** path 出现
  - `evaluate(ctx)` → `evaluate(ctx, null)`；新 `evaluate(JsonReadContext ctx, BranchInputs inputs)`；`ConditionNode.matches(ctx, inputs, evaluation)`：
    ```java
    if (condition.getOp() == JudgeOp.STRATEGY) { boolean hit = inputs != null && inputs.strategyMatched(condition.getValue()); evaluation.record(condition, hit, condition.getValue(), hit); return hit; }
    if (condition.getOp() == JudgeOp.JUDGED) { String judged = inputs == null ? null : inputs.judgedValue(); boolean present = judged != null; boolean hit = condition.getOp().matches(condition, present, judged); evaluation.record(condition, present, judged, hit); return hit; }
    // 其余：ctx == null 时按"取不到值"求值（不能 NPE）
    ```
