- 状态：已批准（用户决策：档 A / 只在既有 `ifmap` 库内操作 / 用 `ifmap` 库 / 修复缺陷）；实现已完成，实现期偏差见 §5.3

- 作者：caijun

## 1. 背景与问题

项目里所有数据库相关测试都跑 **H2 内存库（`MODE=MySQL`）**，共 3 类用法：

| 类别 | 位置 | 数量 |
| --- | --- | --- |
| 测试隔离层 | `ifmap-provider-jdbc/src/test/.../TestSchema.java` | 3 个测试类依赖 |
| 各模块内联 H2 URL | `ifmap-spring-boot-starter`（5 个类）、`ifmap-admin-spring-boot-starter`（4 个类） | 9 个类 |
| demo 运行配置 | `ifmap-demo-spring-boot3/src/main/resources/application.yml` | 1 处 |

H2 无法覆盖的 MySQL 专属语义（已在真库实测确认）：`json` 列的类型校验与规范化、`ENGINE/ROW_FORMAT/COLLATE` 表尾、
`datetime(3)` 毫秒往返、utf8mb4、`deleted_seq` 唯一键语义、STRICT 模式、`ALGORITHM=COPY/LOCK=SHARED`。

已确认的**真实缺陷**（H2 上永远测不出来）：`Logs.truncate` 截断后产生非法 JSON → 写入 MySQL `json` 列报 3140 →
`IfmapOrchestrator.writeLog` 吞掉异常只 WARN → **该条执行日志静默丢失**。迁移脚本 `03-modify-and-index.sql` 又把存量
`request_param`（`text`）改成 `json`，等于把这个缺陷带给存量系统。

CI 里**已有注释状态的 `integration` job**，约定就是 `IFMAP_JDBC_URL/USER/PASSWORD` + `@EnabledIfEnvironmentVariable`。

## 2. 目标与非目标

目标：
1. 一套开关让上述 H2 位置**都能**切到真 MySQL；未设置环境变量时**默认仍是 H2**（开发机与公共 CI runner 零依赖）。
2. 修复执行日志列缺陷（根治），并让回归测试真的能在真库上变红。
3. CI 增加真库 job，让"只在真库成立/不成立"的语义进入门禁。

非目标：
- 不改成"默认跑 MySQL"（会让没有库的开发者与公共 runner 直接红）。
- 不引入 Testcontainers（项目为 JDK8 基线服务，且已有 CI service 约定）。
- 不动 `yfl_*` 等共享库中的数据。

## 4. 设计

### 4.1 ifmap-testkit

`cn.cj.ifmap.testkit.TestDatabases`（JDK8 编译）：

- 开关：`mysqlEnabled()` / `jdbcUrl()` / `username()` / `password()` / `mysqlUrl()`，读 `IFMAP_JDBC_URL|USER|PASSWORD`。
- 前缀：`prefixFor(hint)` —— H2 原样返回 hint（保持现有断言口径，如 `ifmap_`/`bankint_`）；MySQL 返回
  `itt_<sanitize(hint)≤18>_<hex8>_`，登记进待清理集合 + 安装 shutdown hook（同一 hint 在同一 JVM 内固定，
  这样"同一个 H2 库名"的多处调用在真库档下也落到同一组表上）；另外每次解析前缀时顺带跑一次陈旧清扫。
- 静态入口：`dataSource()`（裸数据源，诊断用）、`applyProductionDdl(ds, prefix)`（按档位建 4 张生产表）。
- Schema：`Schema { DataSource dataSource(); String prefix(); }`，工厂
  `fresh(hint)` / `freshWithTables(hint)` / `freshWithArchive(hint)`（分别对应"只给数据源"、"+4 个生产 DDL"、"+归档冷表"）。
- DDL：`read(classpath)`；`toH2(ddl, prefix)`（剥表尾 + `json`→`text`，断言式）；`toMysql(ddl, prefix)`（原样，只做 `${tablePrefix}` 替换与注释/分号规整）。
- Spring 侧：`springProperties(hint)` / `springPropertyArray(hint)` → url/username/password/driver-class-name + `ifmap.table-prefix`，
  供 `ApplicationContextRunner.withPropertyValues(...)` 与 `@SpringBootTest` 的 `@DynamicPropertySource` 使用。
  注意：H2 档下 `prefixFor(hint)` 原样返回 hint ⇒ Spring 测试里"实际前缀"必须一律取 `prefixFor(hint)`，不能写字面量 `ifmap_`。
- 清理（三层）：`drop(prefix)` / `cleanupAll()` / `dropAllTestTables()`（人工用）/ `sweepStaleTestTables(minutes)`；
  `TestDataCleanupListener implements LauncherSessionListener`（`META-INF/services` 自动装配，测试侧零配置）+ shutdown hook + 陈旧清扫。
  `private dropTables(prefix)` 与 `drop(prefix)` 的区分是**必须**的：前者只删表、不动登记；建表前的"先删干净再建"只能走前者。
- 时区：`mysqlUrl()` 成对补 `serverTimezone=<JVM 偏移>` 与 `sessionVariables=time_zone='<JVM 偏移>'`（`+` 需 `%2B` 转义，`Z` 归一成 `+00:00`）——
  只补一个会与 `@@global.time_zone=SYSTEM`（服务器 `@@system_time_zone=UTC`）打架，`datetime(3)` 往返偏移 8 小时。

依赖策略（**实现时推翻了原设计**，见 §5.3）：**testkit 完全不依赖 `spring-jdbc`** —— 用 JDK 原生 `DriverManager` + 私有
`SimpleDataSource` 实现 `DataSource`，于是既不需要 `${spring-jdbc.version}`、也不存在"污染 SB3 的 6.2.x"的风险。
最终依赖：`h2` `compile`、`mysql-connector-j` `compile`、`junit-jupiter` `test`、`junit-platform-launcher` `provided + optional`。

依赖策略（`spring-jdbc` 那条是硬约束）：`h2`/`mysql-connector-j` 显式 `compile`（父 POM 把 h2 管成 test，须覆盖，否则不传递给使用方测试）；
`spring-jdbc` 用 `<scope>provided</scope> + <optional>true</optional>` + `${spring-jdbc.version}` ——
**绝不能进 dependencyManagement**，否则会覆盖 SB3 的 6.2.x（根 POM 里已有这条警告）。

### 4.2 隔离与清理

```
MySQL：CREATE TABLE `itt_<hint>_<hex8>_config` ...   ← 前缀替换 ${tablePrefix}
       ↓ 测试读写（repository / Spring 上下文都指向同一个前缀）
DROP TABLE `itt_<hint>_<hex8>_*`                     ← information_schema 反查后逐个删
```

安全栅栏（三重）：前缀必须匹配 `^itt_[a-z0-9_]{0,18}_[0-9a-f]{8}_$`（hint 允许下划线，如 `ifmap_admin_service`）；
待删表名必须 `startsWith(prefix)`；只查 `TABLE_SCHEMA = DATABASE()`。→ 构造上不可能命中 `ifmap_*`、`bankint_*`。

清理共三层（缺一层就会在真库里积残表，见 §5.3）：

| 层 | 触发时机 | 作用范围 |
| --- | --- | --- |
| `TestDataCleanupListener`（`LauncherSessionListener`） | JUnit 会话结束 | 本 JVM 登记过的前缀 |
| shutdown hook | JVM 正常退出（`Runtime.halt()` 不执行） | 同上 |
| `sweepStaleTestTables(30)` | 每次 `prefixFor()` 一次（本 JVM 只跑一次） | 全库 `itt_*` 中创建时间早于 `NOW() - 30min` 的表 |

另有 `dropAllTestTables()`：只删匹配前缀形状的 `itt_*`，**仅供人工执行**（会误伤并行构建，所以不进自动流程）。
陈旧清扫的判定用 `CREATE_TIME <= DATE_SUB(NOW(), INTERVAL n MINUTE)`（秒级精度下用 `<` 会漏掉正好等于阈值的表）。

### 4.3 改造清单（H2 → 开关）

| 模块 | 改法 |
| --- | --- |
| provider-jdbc `TestSchema` | 内部委托 testkit；返回 `Schema`（DataSource + 实际前缀），3 个测试类的 `TableNameResolver` 改用同一前缀 |
| spring-starter / admin（9 个类） | 内联 H2 URL 片段 → `TestDatabases.springProperties(hint)` / `springPropertyArray(hint)`（`@SpringBootTest` 用 `@DynamicPropertySource`）；

admin 侧额外引入 `AdminTestSupport.Db`（把"名字 → 前缀 → DataSource/JdbcTemplate/表名"绑在一起），避免真库档下多个测试类落到同一组表 |

## 5. 缺陷修复

### 5.1 结论：`request_param` 改回文本（`mediumtext`）

理由（逐条对应实测证据）：

1. **审计日志的正确性要求是"一定写得进去 + 内容忠实"**，而 `json` 列三条都反着来：非法 JSON 直接 3140（日志丢行）；
   `10.00`→`10`、`1.0E10`→`10000000000` 等**规范化破坏刚发布的"小数形态保真"契约**；数字超界（`1e400`）写不进。
2. **截断与 `json` 语义天然冲突**：`truncateThreshold` 默认 64KB，超长即截断，而截断后的文本必然不是合法 JSON。
3. **本来就是不对称的**：`response_param` 已经是 `mediumtext`，只有 `request_param` 是 `json`（迁移脚本改的）。
4. **迁移风险**：`00-precheck.sql §10.5` 必须预检"存量 request_param 是否都是合法 JSON"，改成文本后这个预检不再需要。

被放弃的选项：
- ① "让截断结果保持合法 JSON"（保留 `json` 列）：只能解决截断这一条，规范化/超界/非 JSON 内容仍然丢日志，且需要 JSON 感知的截断实现。
- ④ 只改文档：缺陷仍在。

### 5.3 实现期发现并修掉的两个缺陷

**① 清理登记被建表动作自己注销**（真库积残表的根因）。

`prefixFor(hint)` 把前缀登记进 `MANAGED`，但 `fresh()` 内部的"先按前缀删干净再建"调的是 public `drop(prefix)`，
而 `drop()` 末尾有 `MANAGED.remove(prefix)` ⇒ **建表把这组表从待清理集合里抹掉了**，会话监听器/退出钩子遍历到空集合、
静默什么都不删。实测现象：真库档整轮跑完留下 8 张 `itt_*`（两模块 × 4 张生产表）；诊断打印 `managed=0` 而 `itt=8`。

修法：拆 `private dropTables(prefix)`（只删表，不碰登记）/ `drop(prefix)`（删表 + 注销），`applyProductionDdl` 走前者。
回归守卫 = `ifmap-provider-jdbc` 的 `TestSchemaCleanupTest`（该模块才有生产 DDL 资源，放在 testkit 会因读不到 DDL
变成 ERROR 而非 FAILURE）。验收口径：整轮真库跑完 `information_schema` 里 `itt_*` 计数必须为 **0**（CI 也加了这条门禁）。

**② 设计里的 `spring-jdbc` 依赖是不必要的**。

原设计要给 testkit 加 `spring-jdbc`（于是要处理"不能进 dependencyManagement、否则覆盖 SB3 的 6.2.x"），
但 testkit 只需要一个 `DataSource` ⇒ 用 `DriverManager` + 20 行 `SimpleDataSource` 就够了。
副产好处：testkit 的依赖图里没有任何 Spring，使用者（如 provider-jdbc）的测试不会被动升/降 Spring 版本。

## 6. 测试计划

1. **H2 档（默认）**：全量测试仍须全绿（本轮实测 **JDK17 = 534 / JDK8 = 425**；口径含新增的 `ifmap-testkit` 模块与
   `ExecutionLogPayloadFidelityTest`、`TestSchemaCleanupTest`，未计入的 4 个真库专属用例在 H2 档是 skipped）。
2. **真库档**：`IFMAP_JDBC_URL=...` 跑全量；先在**修复前**跑一次拿到红灯证据（`request_param` json → 3140 → 日志丢行；清理登记回归 → 残留）。
3. **回归用例**：≥ `truncateThreshold` 的报文 → `saveExecutionLog` 后必须能按业务单查回（H2 上恒绿、真库上修复前红）。
4. **CI**：启用 `integration` job（`services: mysql:5.7` 与 `8.0` 双矩阵，env 与 testkit 一致）+ 残留 `itt_*` 门禁。
5. **门禁不退化**：JDK8/JDK17 双档 `mvn clean verify` + SpotBugs 0 缺陷 + `mkdocs --strict`。

## 7. 风险

| 风险 | 处置 |
| --- | --- |
| 测试误删 `ifmap_*` 表 | §4.2 三重栅栏；且**任何 DROP 前先 assert 前缀形状** |
| 真库测试残留表 | 三层清理（§4.2）+ 回归守卫（§5.3）+ CI 门禁：真库 job 跑完断言 `itt_*` 计数为 0 |

| `spring-jdbc` 版本污染 SB3 | testkit 里 `provided + optional`，且不进 dependencyManagement |
| 真库档把时区/编码搞乱导致假绿 | 连接参数显式补齐（§4.1），utf8mb4 用例保留 |
