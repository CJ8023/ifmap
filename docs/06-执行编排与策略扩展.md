# 06 · 执行编排与策略扩展（W4）

> 面向 `ifmap-core` 的 **编排器（Orchestrator）** 与 **策略 SPI**。
> 读完之后你应该能回答：一次"接口调用"到底按什么顺序发生了什么、我在哪一层插手、配置里写错什么会在启动期（而不是线上）被拦下。

---

## 1. 一次调用发生了什么

```java
IfmapResult result = orchestrator.execute(request, "BIZ_APPLY", "apply");
```

`execute` 内部的实际顺序（**每一格都可以被你替换**）：

| # | 步骤 | 由谁决定 | 可替换点 |
|---|---|---|---|
| 1 | 解析租户 | `TenantResolver` | 上下文 `tenantId` > 请求头 `X-Tenant-Id` > 默认 `-1` |
| 2 | 取该业务节点内的**有序步骤计划**，并截断到起点 `interfaceNo` | `ConfigRepository`（`queryConfigsByBusiNode`） | 仓储 SPI / 缓存装饰器 |
| 3 | 排序（`interface_order` 升序，同值 `key_id` 兜底） | `InterfaceOrdering` | — |
| 4 | 逐条配置：组包参数（按 (partnerCode, busiNode)）+ `payload` + **跨步骤共享池** | `FullParamStrategyRegistry` | `FullParamStrategy` |
| 5 | 渲染**请求**模板 | `IfmapEngine` + `RuleRegistry` | `@IfmapRule` |
| 6 | **前序**策略钩子（补字段 / 换报文形态）后**再次渲染** | `StrategyHookRegistry` | `IfmapStrategyHook`（按 `pre_strategy_name`） |
| 7 | 出网 | `PartnerServiceGateway` | 宿主实现（HTTP/SDK/local stub） |
| 8 | 渲染**响应**模板 → 本步骤产物 | `IfmapEngine` | — |
| 9 | **后序**策略钩子（改的是产物，不是回参） | `StrategyHookRegistry` | `IfmapStrategyHook`（按 `post_strategy_name`） |
| 10 | 判定成功/失败；**成功才把本步骤产物写进共享池** | `JudgementPipeline`（通道 → `result_judge` 规格 → 抽取 → 归因） | 判定器 SPI：`judge_name` 换实现 |
| 11 | 命中逻辑分支 → 执行动作 | `LogicBranchStrategyRegistry` + `ActionRegistry` | `@LogicBranch` / `@IfmapAction` |
| 12 | 落执行日志（脱敏 + 截断） | `ExecutionLogSink` / `LogMasker` | `ifmap.log.*` |

失败即停：`stopOnFailure=true`（默认）时某条配置判定失败就不再执行后续配置，但**已执行日志仍会落库**。

### 执行计划：一个业务节点内的一张有序步骤表

一次 `execute` 跑的是**一个业务节点**（如 `apply`）里的**一串有序步骤**，顺序由 `interface_order`
唯一决定（升序，同值按 `key_id` 兜底，见 `InterfaceOrdering.sort`）：

```text
配置：busi_node=apply 的三行
  IF_AUTH  interface_order=1
  IF_RISK  interface_order=2
  IF_APPLY interface_order=3

execute(request, "IF_RISK", "apply")
  → 计划 = [IF_AUTH(1), IF_RISK(2), IF_APPLY(3)]   ← 按 order 升序
  → 起点 = IF_RISK ⇒ 截断为 [IF_RISK, IF_APPLY]     ← 只跑这一段
```

第二个参数 `interfaceNo` 是**起点**：引擎先取该 `busi_node` 的整张计划，再截断到起点；
传 `null` / `""` = 从第一步开始跑全节点。起点写错（停用 / 已删除 / 编号打错）会抛
`IfmapConfigException`，消息里带 `tenantId` / `interfaceNo` / `busiNode` 与纠正方向 ——
**不会静默退化成"什么都没跑"**。

> 引擎不再"按 `interfaceNo` 反查前置链"：以前那套 `front_interface_no` + 拓扑排序 + 环检测（深度护栏 64）
> 已随本次重构删除 —— 「谁是前序」现在只有一个答案，就是 `interface_order`。

### 跨步骤共享池（`pool`）

同一 `busi_node` 内的步骤是**串行**的，后面的步骤可以引用前面步骤的产物：

- 池的键 = **步骤的 `interface_no`**，值 = 该步骤响应模板渲染出的 Map；
- 请求模板里写 `$.pool.IF_AUTH.token` 即可取到 `IF_AUTH` 这一步的产物（语法细节见 [`docs/02`](02-模板DSL语法.md) §2.4）；
- **只有判定成功的步骤才入池**（失败步骤的产物不入池，避免拿半成品往下跑）——
  所以「池里的键集合」=「本轮已成功的步骤集合」= **天然的进度标记**（断点续跑只依赖它）；
- 宿主可以在 `payload` 里带一个初始池（`payload.put("pool", ...)`）当**预置数据**：
  引擎只**读**它、不写回 `payload`；回程产物在 `IfmapResult.data.pool`；
- `IfmapResult.data` 还会把池**展平**到顶层（每个键一个入口），所以老代码读
  `result.getData().get("applyNo")` 不受影响，`data.get("pool")` 才是整池。

前序策略在**入池之前**执行，所以它给当前步骤补的字段不会污染池里其他步骤的数据。

### 前后序策略：两个钩子，不是一个

`IfmapStrategyHook` 带**相位**（`StrategyContext.getPhase()`），两列各管一头：

| 列 | 相位 | 调用位置 | 适合做什么 |
|---|---|---|---|
| `pre_strategy_name` | `PRE` | 请求模板渲染后、**出网前** | 补字段 / 换报文形态 / 加签名 |
| `post_strategy_name` | `POST` | **响应模板渲染后**、判定之前 | 按原始回参补正产物、抹平字段差异 |

- 两列表里写同一个 bean 名是合法的：同一策略被调用两次，按 `context.getPhase()` 区分；
- 后序策略改的是**产物**，**不会**翻转判定结果（判定读的是原始回参，见 §7）。

### 试跑（dry-run）

```java
// 第四个参数 mockResponse 非空时不出网，直接拿它当"资方响应"
IfmapResult r = orchestrator.execute(request, "BIZ_APPLY", "apply", "{\"resultCode\":\"0000\"}");
```

管理端"保存前试跑"就是靠它：**不碰真实资方**，只验证模板 + 判定 + 分支 + 出参映射。

## 2. 公开模型（`cn.cj.ifmap.core.model`）

### IfmapRequest

不可变（`withAttribute` 返回新实例）+ Builder：

```java
IfmapRequest request = IfmapRequest.builder()
        .tenantId("1001")            // 不填则走 TenantResolver
        .operatorId("zhangsan")
        .requestId("REQ-20250101-001")
        .bizId("BIZ-20250101-0001")  // 业务主键，日志里可反查
        .header("X-Channel", "APP")  // 请求头（大小写不敏感）
        .put("orgCode", "12")        // payload：模板渲染的源数据
        .put("acctName", "张三")
        .attribute("workday", true)  // attributes：给条件/规则用的环境信息
        .build();
```

| 方法 | 说明 |
|---|---|
| `of(Map<String,Object>)` | 直接拿一个 Map 当 payload（等价于 `builder().payload(map).build()`） |
| `empty()` | 空请求（只做渲染时用） |
| `getHeader(name)` | 大小写不敏感取头，未命中返回 `null` |
| `getAttribute(key)` | 取 attributes |
| `withAttribute(k,v)` | 返回**新**实例，不改原件 |

### IfmapResult

```java
IfmapResult.success(dataMap);      // 便捷构造
IfmapResult.failure("余额不足");    // 便捷构造
```

| 方法 | 说明 |
|---|---|
| `isSuccess()` | 判定结果 |
| `getData()` | 各步骤产物的 Map + **展平的共享池** + `pool` 键（整池）；无产物时为空 Map |
| `getRawResponse()` | 资方原始响应报文（最后一步的） |
| `getExecutedInterfaces()` | 实际发起过调用的接口号，**按执行顺序**（含判定失败者；「已成功的步骤」看 `data.pool` 的键集合） |
| `getMatchedBranch()` | 命中的 `logic_branch_flag`，未命中为 `null` |
| `getElapsedMs()` | 耗时（`ClockProvider` 计时，测试可注入假时钟） |
| `getErrorMessage()` | 失败原因 |

## 3. 三类策略 SPI（对应存量三工厂）

> 共同点：**都是普通接口**。宿主机写一个 `@Component` 实现类即可，starter 自动注册（见 §5），
> **不再有**"按 bean 名反射调方法"的隐式约定。
>
> 本节只讲三类策略 + 动作；**全部扩展点（含 `ConfigRepository` / `ClockProvider` / `HolidayCalendar`
> 这类非策略 SPI）以及「不给会怎样」见 §11。**

| 接口 | 注册键 | 注解 | 何时被调用 |
|---|---|---|---|
| `IfmapStrategyHook` | **bean 名**（与 `ifmap_config.pre_strategy_name` / `post_strategy_name` 对齐） | 无（靠 bean 名） | 请求渲染后（相位 `PRE`）/ 响应渲染后（相位 `POST`），可改报文或补产物 |
| `FullParamStrategy` | `partner|busi` | `@FullParam(partnerCode=..., busiNode=...)` | 每条配置渲染**前**组装公共参数 |
| `LogicBranchStrategy` | 分支 flag | `@LogicBranch("...")` | 判定后，判断"这条分支算不算命中" |
| `IfmapActionHandler` | 动作 key | `@IfmapAction("...")`（**类级注解**） | 分支命中后执行落地动作 |

> `IfmapStrategyHook` 的注册键除 **bean 名**外，还兼容「类简单名」与「首字母小写变体」两种历史写法
> （命中时记一条 WARN，建议改成 bean 名）。这一层宽容是**为存量 P0-7 准备的**，见
> [`docs/10`](10-迁移指南.md) §4.1。

```java
@Component
@FullParam(partnerCode = "CMB", busiNode = "apply")
public class CmbApplyFullParam implements FullParamStrategy {
    @Override
    public Map<String, Object> assemble(StrategyContext context) {
        Map<String, Object> full = new LinkedHashMap<>();
        full.put("partnerCode", "CMB");
        full.put("channelCode", "ECC");
        return full;   // 会成为请求模板渲染源的一部分（模板里写 $.partnerCode 即可取到）
    }
}
```

### IfmapStrategyHook：前序改"报文"，后序改"产物"

同一个接口，两个相位拿到的东西不一样（`StrategyContext.getPhase()` 告诉你是哪一个）：

| 相位 | 触发时机 | 你怎么改 | 返回值怎么用 |
|---|---|---|---|
| `PRE`（`pre_strategy_name`） | 请求模板渲染后、出网前 | `context.setRequestJson(...)` 直接换报文 | **合并进渲染参数后重新渲染请求模板** → 既能补字段，也能整体换形态 |
| `POST`（`post_strategy_name`） | 响应模板渲染后、判定前 | `context.setResponseData(...)` 换掉产物 | 换掉 / 合并进**产物**（`IfmapConfig` 的响应模板已跑完），判定读的仍是原始回参 |

```java
@Override
public Map<String, Object> apply(StrategyContext context) {
    if (context.getPhase() == StrategyContext.Phase.POST) {
        // 产物修正：抹平资方字段差异（getResponseData() 是 Object，直接换整份产物）
        Map<String, Object> fixed = new LinkedHashMap<>();
        fixed.put("applyNo", context.getResponseJson() == null ? "" : "PARSED");
        context.setResponseData(fixed);
    }
    return Collections.emptyMap();   // 也可直接返回要额外并入的字段
}
```

前序写法（改成报文形态）见下面这段：

```java
@Component   // bean 名 = czbApplyStrategy → 配置里 pre_strategy_name 写 czbApplyStrategy
public class CzbApplyStrategy implements IfmapStrategyHook {
    @Override
    public Map<String, Object> apply(StrategyContext context) {
        // 拿到当前报文、模板、配置、RuleContext，随便改
        context.setRequestJson("{\"wrapper\": ...}");
        return Collections.singletonMap("signType", "RSA2");
    }
}
```

- 返回 `null` 或空 Map = 不改。
- `pre_strategy_name` / `post_strategy_name` 之一有值但**没有对应策略** → 默认**抛 `IfmapStrategyException`**（`ifmap.orchestrator.fail-on-missing-strategy=false` 时可降级为 WARN 跳过）。
- 异常消息会列出**所有已注册的 key**，便于直接对照修正（存量"11/38 不一致"就是这么炸的）。

### FullParamStrategy：查找顺序是显式契约

`lookup(partnerCode, busiNode)` 依次尝试，**先精确后通配**：

```text
CMB|apply  →  CMB|*  →  *|apply  →  *|*
```

`contains(partnerCode, busiNode)` / `keys()` 可在保存前校验里用来判断"这家银行到底有没有配组包策略"。

### LogicBranchStrategy vs `logic_branch_value`

分支是否命中，**两条路任一成立即可**（`matches` 里 or 关系）：

1. `logic_branch_flag` 有值且注册了同名 `@LogicBranch` 策略 → 调它的 `match(ctx)`（复杂条件，如"金额 > 100 万且渠道=APP"）；
2. `logic_branch_value` 有值且与判定取到的实际值相等（多值用 `;` 或 `,` 分隔，大小写不敏感）。

都判定为"未命中"时落 WARN 日志，`getMatchedBranch()` 为 `null`；配置写错（flag 与 value 都为空）会额外 WARN 指出 `key_id`。

### 动作（替代 `method_flag` 反射）

```java
@Component
@IfmapAction("submit")            // 注解写在类上（TYPE 级）
public class SubmitAction implements IfmapActionHandler {
    @Override
    public void execute(StrategyContext context) {
        // context.getInterfaceNo() / getBizId() / getMatchedBranch() / getResponseData()
    }
}
```

- 动作 key 取 `method_flag`；`method_flag` 为空时退化为用 `logic_branch_flag`。
- **缺失动作默认快速失败**（`fail-on-missing-action=true`）；置 `false` 时 WARN 跳过。

## 4. StrategyContext（策略能看到什么）

| 方法 | 内容 |
|---|---|
| `getRequest()` | 本次 `IfmapRequest`（租户/业务号/操作人/头/属性） |
| `getConfig()` | 当前 `IfmapConfig`（含 `interfaceNo` / `partnerCode` / 模板原文） |
| `getPhase()` | 当前相位：`PRE`（前序）/ `POST`（后序）；默认 `PRE` |
| `getRuleContext()` | 渲染用的 `RuleContext`（租户、接口号、attributes） |
| `getParams()` | 当前渲染参数（组包 + 策略钩子的结果都在里面） |
| `getRequestJson()` / `setRequestJson(...)` | 出网报文（策略钩子可直接改写） |
| `getResponseJson()` / `setResponseJson(...)` | 资方原始响应报文 |
| `getResponseData()` / `setResponseData(...)` | 已渲染的产物 Map（**后序相位**里改它即为修正产物） |
| `getMatchedBranch()` | 命中分支 flag |
| `getInterfaceNo()` / `getBizId()` | 便捷取用（空安全） |
| `putParam(k,v)` / `putParams(map)` | 追加渲染参数 |

## 5. Spring Boot 里需要做什么（starter 自动收集）

只要你的策略类是个 Spring bean，**什么都不用配**：

| 你的 bean 实现了 | starter 用它注册到 |
|---|---|
| `IfmapStrategyHook` | `StrategyHookRegistry`，key = **bean 名** |
| `FullParamStrategy`（带 `@FullParam`） | `FullParamStrategyRegistry` |
| `LogicBranchStrategy`（带 `@LogicBranch`） | `LogicBranchStrategyRegistry` |
| `IfmapActionHandler`（带 `@IfmapAction`） | `ActionRegistry` |
| `IfmapCallbackHandler`（带 `@IfmapCallback`） | `CallbackRegistry`，key = 接口号 |
| 方法带 `@IfmapRule` 的任意 bean | `RuleRegistry`（W3 能力） |

**启动期快速失败**：实现了策略接口但**缺注解**（`@IfmapAction` / `@FullParam` / `@LogicBranch` / `@IfmapCallback`），
启动即抛 `IllegalArgumentException` 并指出 **bean 名 + 类名** —— 不把问题留到线上第一次调用。

注解查找会**沿父类链与接口链**进行（`Annotations.find`），所以被 Spring AOP/CGLIB 代理过的 bean 也能正确识别。

想完全接管某一层？声明同类型 bean 即可（starter 所有 bean 都是 `@ConditionalOnMissingBean`）：

```java
@Bean
IfmapOrchestrator ifmapOrchestrator(IfmapEngine engine, ConfigRepository repository) {
    return IfmapOrchestrator.builder()
            .engine(engine).repository(repository).tenantResolver(new MyTenantResolver())
            .stopOnFailure(false)
            .build();
}
```

### 相关配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| `ifmap.tenant-header` | `X-Tenant-Id` | 取租户的请求头名 |
| `ifmap.default-tenant-id` | `-1` | 都取不到时的兜底租户 |
| `ifmap.orchestrator.stop-on-failure` | `true` | 失败即停 |
| `ifmap.orchestrator.fail-on-missing-strategy` | `true` | `pre_strategy_name` / `post_strategy_name` 找不到策略时是否快速失败 |
| `ifmap.orchestrator.fail-on-missing-action` | `true` | 动作未注册时是否快速失败 |
| `ifmap.log.enabled` | `true` | 是否装配执行日志落库 |
| `ifmap.log.truncate-threshold` | `65536` | 单条报文落库最大长度，超出打标 `...truncated` |
| `ifmap.log.mask-fields` | 空（= 内置姓名类字段） | 按**字段名**脱敏的字段 |
| `ifmap.log.exclude-fields` | 空 | 这些字段**整体**替换为 `***` |

> `mask-fields` 留空 = 用内置默认（`acctName` / `accountName` / `certName` / `userName` / `realName` / `legalName` / `legalPerson` / `contactName`）。
> 想**完全关闭**按字段名脱敏，请自定义 `LogMasker` bean（属性留空不代表"关闭"，否则姓名会被原样落库）。

## 6. 脱敏与截断（合规）

`DefaultLogMasker`（core 内置，零依赖）对**要落库的报文**做两件事：

| 形态 | 处理 | 示例 |
|---|---|---|
| `phone` / 手机号 | 中间打星、保留头 3 尾 4 | `13812348888` → `138****8888` |
| 身份证 | 保留头 6 尾 4 | `320102199001011234` → `320102********1234` |
| 银行卡 | 保留头 6 尾 4（13~19 位） | `6222021234567890` → `622202******7890` |
| 姓名字段 | 只留首字 | `张三` → `张*`、`张小三` → `张**` |
| `exclude-fields` | 整体替换 | `idCard` → `***` |
| `null` / 非 JSON | 原样返回（不抛异常） | — |

- 幂等：已经脱敏过的报文再过一遍结果不变（不会越脱越短）。
- 值形态识别**含不加引号的数字**（`"acctNo":6222021234567890` 同样脱敏）；
  短号与金额不动（`{"amount":"1000.00","seq":"123456","count":3}` 原样返回）。
- **嵌套 JSON 字符串内部不脱敏**（`{"sub":"{\"mobile\":\"13812348888\"}"}` 原样返回）——
  避免把已转义的报文改坏。
- 截断在脱敏之后做：超 `truncate-threshold` 的报文尾部替换为 `...truncated`（常量 `Logs.TRUNCATED`）。

```java
LogMasker masker = new DefaultLogMasker();
masker.mask("{\"mobile\":\"13812348888\"}");   // {"mobile":"138****8888"}
```

> 日志落地后还有两件事：**保留期清理**（默认 90 天，分批删除 + 定时任务）与**写日志失败的降级**；
> 连同合规自查清单见 [`docs/08-日志与合规.md`](08-日志与合规.md)。

## 7. 判定（`result_judge` 规格 + 判定管线）

判定只有**一个入口**：配置列 `result_judge`（`text`，**必填**）。它是 JSON 规格文本，
由 core 的 `ResultJudgeSpec` 解析求值；`judge_name` 可以换成别的判定器实现（空 = 默认 `ruleSpec`）。

```json
// ① 恒真：不需要判断结果（仍受通道 / HTTP 状态约束）
{"op": "always"}

// ③ 条件判定：code 等于 0000，或 state ∈ {SUCCESS, INIT}
{"any": [{"path": "$.code", "op": "eq", "value": "0000"},
         {"path": "$.state", "op": "in", "value": ["SUCCESS", "INIT"]}]}
```

顶层**只有两种合法形态**（外加一种非法形态，三者互不退化）：

| 形态 | 写法 | 校验 | 运行期 |
|---|---|---|---|
| ① 恒真（不判定） | `{"op":"always"}`，**不允许再带 `path`/`value`/`ignoreCase`** | 合法 | 恒成功，**短路：不解析响应** |
| ② 空组合 | `""` / `{}` / `{"all":[]}` / `{"any":[]}` / 缺列 | **非法**（不再解释成恒真） | fail-closed：判失败 + `fail_type=SPEC_INVALID` + WARN，**不抛异常** |
| ③ 条件判定 | `{"all|any":[{path, op, value?, ignoreCase?}]}`，至少 1 条 | 合法 | 正常求值 |

`op` 是闭合集合（7 个，未知值即 `SPEC_INVALID`）：

| op | 语义 | 备注 |
|---|---|---|
| `eq` / `ne` | 实际值 `=` / `≠` `value` | 存量 `!a` 的正式表达是 `ne` |
| `in` / `notIn` | 实际值 `∈` / `∉` `value`（**非空数组**） | 替代旧 `success_value` 的多值 |
| `exists` | JsonPath 能取到（值可为 `null`） | 区分「字段缺失」与「字段值为空」 |
| `notBlank` | 取到的值非 `null` 且 trim 后非空 | 替代旧「`success_value` 为空 = 非空即成功」；**`0`/`false` 算非空**（不再有 falsy 魔法） |
| `regex` | 实际值匹配 `value`（Java 正则） | |

其他口径：

- 比较按**字符串**做；`ignoreCase` **默认 `false`（严格相等）**，要忽略大小写必须显式写 `"ignoreCase":true`
  —— 判定是资金链路的仲裁点，宽松默认会吃掉 `SUCCESS` 与 `success` 的差异（**与旧 `success_value` 相反，属已声明的行为变更**）
- `path` 走 JsonPath（与模板 DSL 同一实现）；`all`/`any` 嵌套上限 **3 层**
- 判定失败**不走分支/动作**（与旧行为一致）；判定结果只**记录**，引擎不做重试/熔断

### 7.1 判定管线（四段）

```text
① 通道：宿主上报的 statusCode / 超时 → 非 2xx / TIMEOUT 立即失败，不再求值规格
② 业务：ResultJudge SPI（默认 ruleSpec）按 result_judge 求值
③ 抽取：固定候选路径取 message / trackId（`$.message` → `$.msg` → `$.error` → `$.detail` → `$.errorMessage`；
        trackId：$.trackId → $.track_id → $.requestId → $.serialNo），只影响日志，不改判定结论
④ 归因：fail_type 枚举落库
```

`fail_type`（成功为空串，闭合 9 值）：`TRANSPORT` / `TIMEOUT` / `HTTP_4XX` / `HTTP_5XX` /
`SPEC_INVALID` / `NOT_JSON` / `FIELD_MISSING` / `VALUE_MISMATCH` / `EXTRACT_FAILED`（仅 WARN）。

`Judgement` 里除 `actual` / `expected` / `reason` 外还有 `httpStatus` / `trackId` / `errorCode`，
都进执行日志（见 [`docs/04`](04-接入与建表.md) §8.3）。

### 7.2 换判定器（SPI）

```java
public interface ResultJudge {
    String name();                                 // 注册名，如 ruleSpec / partnerAck
    Judgement judge(ResultJudgeContext context);    // config + responseJson + jsonOps
}
```

`judge_name` 非空按名取注册表，空则用默认 `ruleSpec`；注册名大小写不敏感（不一致会在日志里 WARN）；
**名字拼错不会回落默认判定器**，而是 `fail_type=SPEC_INVALID` fail-closed —— 静默换成默认规则，等于"以为按资方规则判、其实没判"。
自定义实现必须遵守：**不抛异常**（失败返回 `Judgement.failure`），否则判定失败会变成整条链路异常。

### 7.3 与存量的差异（迁移必读）

| 存量写法 | ifmap 写法 |
|---|---|
| `result_flag` + `success_value` 两列 | 单列 `result_judge` 规格 |
| `result_flag` 为空 = 成功 | 显式 `{"op":"always"}`（空/缺列现在是**非法**） |
| `success_value` 多值 `a,b`（`,`/`;`） | `{"op":"in","value":["a","b"]}`（**大小写敏感**，需要忽略须加 `"ignoreCase":true`） |
| `success_value` 取反 `!a` | `{"op":"ne","value":"a"}` |
| `success_value` 为空 = 非空即成功 | `{"op":"notBlank"}`（`0`/`false` 现在算成功，要判 `0` 请写 `eq`） |

## 8. 契约自检（部署前跑一次）

```java
ContractReport report = new ContractValidator(engine).validate(repository.queryConfigs("1001", "BIZ_APPLY", "apply"));
if (!report.isClean()) {
    log.error("ifmap 配置契约有问题：\n{}", report.toMarkdown());
}
```

检查项：

| 检查 | 拦截的线上事故 |
|---|---|
| 模板是合法 JSON（请求 + 响应两侧） | 手改模板漏了个引号 |
| `@FUN(name,...)` 的 `name` 已注册 | `farmatDate` 这类拼写错误 |
| `@FUN` 参数个数/类型能匹配到某个重载 | 少传参数的静默 null |
| `result_judge` 规格合法（空/`all:[]`/未知 op/嵌套超限/`always` 带 `path`） | 运行期每条都判失败，且**不报错** —— 只在日志里静默 |
| 判定形态统计（条件判定 / 不判定各多少条） | 「以为配了校验，其实全是 `always`」的审计盲区 |

`report.toMarkdown()` 可直接贴 CI 产物或工单；零违规时输出"零违规"字样（测试里就是这么断言的），
末尾附「判定形态统计」（接口总数 / 不判定 / 条件判定）。`report.judgeSpecViolations()` 可单独筛出判定类违规。

IfmapOrchestrator orchestrator = IfmapOrchestrator.builder()

## 11. 扩展点（SPI）总览

> **一句话口径**：下表标「**无**」的 4 处（`ConfigRepository` / `PartnerServiceGateway` / `HolidayCalendar` / `IfmapEnumProvider`）没有内置实现，
> 其余扩展点都有。Spring Boot 路径下**不写任何一行代码也能跑通全链路**（内置实现全部带 `@ConditionalOnMissingBean`，
> 宿主声明同类型 bean 即完全接管，见 [`docs/05`](05-SpringBoot集成.md) §3.1）；纯 Java 路径下 `ConfigRepository` / `TenantResolver`
> 必须在 Builder 里显式传入（见 §10）。

| 扩展点 | 职责 | 内置实现 | 未提供时的行为 |
|---|---|---|---|
| `ConfigRepository` | 查配置：`queryConfigs(tenantId, interfaceNo, busiNode)` / `findConfig(...)` / `queryLogicBranches(...)` / **`queryConfigsByBusiNode(tenantId, busiNode)`**（返回该节点内按 `interface_order` 升序、只含启用且未删除的步骤） | **无**（`ifmap-provider-jdbc` 给 JDBC 实现，`ifmap-provider-remote` 给远端实现） | **必填**：`IfmapOrchestrator.Builder.build()` 抛 `IllegalArgumentException` |
| `TenantResolver` | 解析租户号 | `HeaderTenantResolver`（上下文 > 请求头 > 默认 `-1`） | **必填**（同一入口校验）；Spring Boot 下 starter 会自动注册默认 bean |
| `PartnerServiceGateway` | 出网调用合作方 | **无**（只有 `ifmap-demo-spring-boot3` 里的 `DemoPartnerGateway`） | **不出网**：只做本地渲染，等价 dry-run，日志 WARN（见 §1「试跑」） |
| `HolidayCalendar` | `workdayAdd` 判断调休 / 法定节假日 | **无** | 简化口径「周一~周五工作日、周六周日休息」，**不感知法定节假日与调休** |
| `IfmapEnumProvider`（admin） | 管理端页面字典下拉 | **无** | `/enums` 返回 `200 {}`（**不是 404**），页面退化成纯文本输入（见 [`docs/07`](07-管理端REST.md) §11.3） |
| `JsonOps` | JSON 读写（模板渲染 / 响应解析 / 数字保真） | `JacksonJsonOps`（classpath 有 Jackson 时自动装配）；`FastjsonJsonOps` 需显式引入并声明 bean（见 [`docs/05`](05-SpringBoot集成.md) §3.2） | 两类实现都不在 classpath 时无 `JsonOps` bean → **必填**（引擎起不来） |
| `ResultJudge` | 成败判定：`name()` + `judge(ResultJudgeContext)`，读 `result_judge` / 响应报文出 `Judgement` | `RuleSpecJudge`（规格求值，注册名 `ruleSpec`） | 配置列 `judge_name` 为空即用 `ruleSpec`；按名找不到 → `fail_type=SPEC_INVALID` fail-closed（**不回落到默认判定器**，否则拼错名字会静默按错规则判成功） |
| `ExecutionLogSink` | 执行日志落库 | `RepositoryExecutionLogSink`（写 `ifmap_execution_log`） | 不落库（`ifmap.log.enabled=false`），主链路与判定照常 |
| `LogMasker` | 日志脱敏 | `DefaultLogMasker`（手机 / 证件 / 卡号按**值形态**、姓名按**字段名**） | 走默认脱敏（见 §6） |
| `ClockProvider` | 取当前时间 | `SystemClockProvider.INSTANCE` | 系统时钟（单测可注入假时钟，不必 `sleep`） |
| `IdGenerator` | 主键 / 流水号生成 | `SnowflakeIdGenerator`（雪花；`shared()` 为 JVM 单例） | 雪花；`ifmap.id.strategy=auto_increment` 时改由库自增 |
| `ConfigCache` | 配置查询缓存（只缓存 `queryLogicBranches`，key 含 `tenantId`） | `CaffeineConfigCache`（classpath 有 Caffeine）否则回退 `InMemoryConfigCache`（core 自带的零依赖 LRU + 惰性 TTL） | `ifmap.cache.enabled=false` 时直查配置库 |
| `IfmapStrategyHook` / `FullParamStrategy` / `LogicBranchStrategy` / `IfmapActionHandler` / `IfmapCallbackHandler` | 三类策略 + 动作 + 回调 | 空注册表（Spring Boot 下 starter 从容器按注解自动收集，见 §5） | 对应环节不执行（见 §3） |

### 为什么这几处「刻意不给默认实现」

它们的取值**只有宿主知道**，给一个默认值等于替宿主做一个静默的业务决定：

| 扩展点 | 硬塞一个默认值会怎样 |
|---|---|
| `ConfigRepository` | 没有「默认配置库」这种普适答案（JDBC / 远端 HTTP / 复用存量表，见 [`docs/11`](11-远端配置源.md)）。给个内存空实现，会让「配置查不到」从启动期报错退化成静默空跑 |
| `PartnerServiceGateway` | 没有「默认合作方」。给一个假定协议的 HTTP 实现，会把**协议不匹配**变成运行期难查的超时 / 400；不给则退化成不出网的 dry-run，安全且日志 WARN 明说 |
| `HolidayCalendar` | 「今天算不算工作日」是**业务日历**（各银行调休安排不同）。「只跳周末」是**写在文档里的已知简化**，比内置一份会过期的法定节假日表更诚实 |
| `IfmapEnumProvider` | 码值含义是宿主业务（设计 Q8：ifmap 不建字典表、不解释业务枚举语义）。页面退化成普通输入框，不影响任何功能 |
| `ResultJudge` | 它**有**默认实现（`ruleSpec` 覆盖绝大多数「取字段比期望值」的场景）；需要按资方定制判定逻辑时再注册 bean，`judge_name` 指名使用。自定义实现必须**不抛异常**（失败返回 `Judgement.failure`），否则判定失败会变成整条链路异常 |
