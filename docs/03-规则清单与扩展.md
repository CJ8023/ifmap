# ifmap 规则清单与扩展

> 适用版本：`0.1.0-SNAPSHOT`　作者：caijun
>
> 本清单与 `IfmapEngine.describeRules()` 输出一致（共 **18 个规则名 / 30 个规则方法**）。
> 生成命令：`System.out.println(engine.describeRules());`

---

## 1. 通用约定

| 约定 | 说明 |
| --- | --- |
| 返回类型 | 报文里的值基本都是字符串，因此**金额/日期规则统一返回 `String`** |
| 金额舍入 | 所有金额舍入都必须**显式**给小数位与舍入方式，避免各家机构各写一套 |
| `allowNullArgs` | 注解属性；`false` 时（默认）任一参数为 null → 该字段按空值策略处理，**规则不被调用** |
| 上下文注入 | 规则方法**第一个参数**声明为 `RuleContext` 即自动注入，模板里不用传 |
| 形参类型 | 标量一律用 `String`；形参是 `String` 而实参是 `List` → **自动逐元素映射**并收集结果 |
| 异常 | 入参非法抛 `RuleArgumentException`（消息面向配置人员）；规则内部异常包成 `RuleInvocationException` |

## 2. 字符串规则

| 规则 | 签名 | null 入参 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `concat` | `concat(Object...)` | 是 | 多值拼接，null 按空串 | `@FUN(concat,$.province,$.city,$.district)` |
| `strDefault` | `strDefault(String,String)` | 是 | null **或空串**时返回默认值 | `@FUN(strDefault,$.remark,无)` |
| `strTruncate` | `strTruncate(String,Integer)` | 否 | 按最大长度截断 | `@FUN(strTruncate,$.remark,50)` |
| `strTruncate` | `strTruncate(String,Integer,String)` | 否 | 截断并追加后缀 | `@FUN(strTruncate,$.remark,50,...)` |
| `strMask` | `strMask(String,String)` | 否 | 按类型脱敏 | `@FUN(strMask,$.idCard,ID_CARD)` |
| `strMask` | `strMask(String,String,Integer,Integer)` | 否 | 保留头 `keepPrefix` 位、尾 `keepSuffix` 位 | `@FUN(strMask,$.bankCard,BANK_CARD,4,3)` |

**`strMask` 内置类型与默认保留位数**

| type | 保留头/尾 | 示例输入 → 输出 |
| --- | --- | --- |
| `ID_CARD` | 4 / 2 | `320123199001011234` → `3201************34` |
| `MOBILE` | 3 / 2 | `13800138000` → `138******00` |
| `BANK_CARD` | 4 / 3 | `6222021234567890123`（19 位）→ `6222************123`（12 个星） |
| `NAME` | 1 / 0 | `张三` → `张*` |
| `EMAIL` | 保留域名 | `zhangsan@x.com` → `z*******@x.com` |

> `strTruncate`：`maxLength` 为 null 或 ≤0 时**不截断**；字符串本身不超长时**不追加后缀**。
> `strMask`：长度 ≤1 或 `prefix + suffix >= 长度` 时原样返回；**长度不足也会打星**（`strMask("abc","NAME")` = `a**`）；
> 未知 type 原样返回（不报错，方便模板平滑迁移）。上表示例值均由 `BuiltinRulesTest#stringRules` 覆盖。

## 3. 码值翻译规则

| 规则 | 签名 | null 入参 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `dictVal` | `dictVal(String,String)` | 是 | 单值翻译，未命中返回 null | `@FUN(dictVal,$.status,01:待处理;02:已处理)` |
| `dictVal` | `dictVal(String,String,String)` | 是 | 单值翻译，未命中返回默认值 | `@FUN(dictVal,$.status,01:待处理,未知)` |
| `dictValArray` | `dictValArray(List,String)` | 是 | 数组逐元素翻译，保持顺序 | `@FUN(dictValArray,$.invoiceTypes,01:专票;02:普票)` |
| `dictValArray` | `dictValArray(List,String,String)` | 是 | 数组翻译，未命中返回默认值 | `@FUN(dictValArray,$.invoiceTypes,01:专票,其他)` |

### 3.1 表达式格式

```
键1:值1;键2:值2;键3:值3
```

| 规则 | 说明 |
| --- | --- |
| 分隔符 | `;` 分隔映射对，**不能用逗号**（`@FUN` 参数按半角逗号切分） |
| 键值分隔 | 优先 `:`；若无 `:` 则回退用 **首个** `-` 分隔（兼容存量写法） |
| 值的特殊字符 | 值里含 `-` **不会**被截断（按首个分隔符切分，存量引擎会截断） |
| 匹配方式 | 键做 `trim` 后**精确**匹配（`"01"` ≠ `"1"`） |
| 空表达式 / 无映射对 | 抛 `RuleArgumentException` |
| 数组翻译遇 null 元素 | 跳过该元素（结果长度可能变短） |

```json
"invoiceTypeName": "@FUN(dictVal,$.invoiceType,01:增值税专用发票;02:增值税普通发票,其他)",
"invoiceTypeNames": "@FUN(dictValArray,$.invoiceTypes,01:专票;02:普票;09:其他)"
```

## 4. 日期规则

解析统一走**宽松模式**：先按常见日期时间格式试，再按日期格式试，最后识别 10 位秒级/13 位毫秒级时间戳；
**全部失败返回 null**（+ WARN，不中断渲染）。

支持的内置格式（无需显式声明即可解析）：

- 日期时间：`yyyy-MM-dd HH:mm:ss`、`yyyy-MM-dd'T'HH:mm:ss`、`yyyy-MM-dd HH:mm:ss.SSS`、`yyyy-MM-dd HH:mm`、`yyyy/MM/dd HH:mm:ss`、`yyyyMMddHHmmssSSS`、`yyyyMMddHHmmss`、`yyyyMMddHHmm`、ISO
- 日期：`yyyy-MM-dd`、`yyyy/MM/dd`、`yyyy.MM.dd`、`yyyyMMdd`、`yyyy-MM`、`yyyyMM`、ISO
- 时间戳：10 位（秒）、13 位（毫秒）

| 规则 | 签名 | 说明 | 示例 |
| --- | --- | --- | --- |
| `dateFormat` | `dateFormat(String)` | 默认输出 `yyyy-MM-dd` | `@FUN(dateFormat,$.dueDate)` |
| `dateFormat` | `dateFormat(String,String)` | 宽松解析后按 pattern 输出 | `@FUN(dateFormat,$.dueDate,yyyyMMdd)` |
| `dateConvert` | `dateConvert(String,String,String)` | 按**显式源格式**解析，再按目标格式输出 | `@FUN(dateConvert,$.dueDate,yyyyMMdd,yyyy-MM-dd)` |
| `dateAdd` | `dateAdd(String,Integer)` | 加减天数 | `@FUN(dateAdd,$.dueDate,3)` |
| `dateAdd` | `dateAdd(String,Integer,String)` | 指定单位 `DAY/MONTH/YEAR/HOUR/MINUTE/SECOND` | `@FUN(dateAdd,$.dueDate,1,MONTH)` |
| `dateAdd` | `dateAdd(String,Integer,String,String)` | 指定单位与输出格式 | `@FUN(dateAdd,$.dueDate,1,MONTH,yyyyMMdd)` |
| `dateDiff` | `dateDiff(String,String)` | 天数差（后者减前者） | `@FUN(dateDiff,$.startDate,$.endDate)` |
| `dateDiff` | `dateDiff(String,String,String)` | 指定单位 | `@FUN(dateDiff,$.startDate,$.endDate,MONTH)` |
| `dateEndOfMonth` | `dateEndOfMonth(String,String)` | 所在月最后一天 | `@FUN(dateEndOfMonth,$.dueDate,yyyy-MM-dd)` |
| `workdayAdd` | `workdayAdd(RuleContext,String,Integer)` | 工作日加减，默认跳过周末 | `@FUN(workdayAdd,$.dueDate,3)` |
| `workdayAdd` | `workdayAdd(RuleContext,String,Integer,String)` | 工作日加减 + 输出格式 | `@FUN(workdayAdd,$.dueDate,3,yyyyMMdd)` |

**`dateFormat` vs `dateConvert`**：`dateFormat` 走宽松解析（源格式随数据变化时更省事）；
`dateConvert` 只按你给的源格式解析（源数据格式可控、要求严格时用它）。

**`workdayAdd` 与节假日**：默认口径「周一~周五工作日、周六周日休息」。
法定节假日 / 调休需宿主提供 `HolidayCalendar`：

```java
RuleContext ctx = RuleContext.builder()
        .attribute(RuleContext.ATTR_HOLIDAY_CALENDAR, (HolidayCalendar) date -> !holidays.contains(date))
        .build();
```

## 5. 金额与数值规则

| 规则 | 签名 | 说明 | 示例 |
| --- | --- | --- | --- |
| `numRound` | `numRound(String,Integer)` | 舍入到小数位，默认 `HALF_UP` | `@FUN(numRound,$.amount,2)` |
| `numRound` | `numRound(String,Integer,String)` | 指定舍入方式 | `@FUN(numRound,$.amount,2,HALF_UP)` |
| `numSum` | `numSum(List)` | 列表按数值求和 | `@FUN(numSum,$.amounts)` |
| `numSum` | `numSum(List,Integer,String)` | 求和 + 舍入 | `@FUN(numSum,$.amounts,2,HALF_UP)` |
| `numOffset` | `numOffset(String,Integer)` | 数值加减整数 | `@FUN(numOffset,$.index,1)` |
| `numFormat` | `numFormat(String,String)` | 金额格式转换 | `@FUN(numFormat,$.amount,CENT_TO_YUAN)` |

**`numFormat` 的 style**

| style | 语义 | `100.5` → | `10` → |
| --- | --- | --- | --- |
| `PLAIN`（默认） | 原样输出，不补位 | `100.5` | `10` |
| `STRIP_ZERO` | 去掉多余的 0 | `100.5` | `10` |
| `THOUSAND` | 千分位 + 固定 2 位小数 | `100.50` | `10.00` |
| `CENT_TO_YUAN` | 分 → 元（÷100，固定 2 位，`HALF_UP`） | `1.01` | `0.10` |
| `YUAN_TO_CENT` | 元 → 分（×100，整数位，`HALF_UP`） | `10050` | `1000` |

**舍入方式**：`HALF_UP`（默认）、`UP`、`DOWN`、`HALF_EVEN`、`CEILING`、`FLOOR`（即 `java.math.RoundingMode` 名称）。

**`numSum` 与列表**：非数值元素按 `0` 计；`numSum` 形参就是 `List`，所以**不会**触发逐元素映射，
返回的是一个总和字符串。要去掉多余 0 用 `numFormat STRIP_ZERO`。

## 6. 列表规则

| 规则 | 签名 | 说明 | 示例 |
| --- | --- | --- | --- |
| `listJoin` | `listJoin(List,String)` | 用分隔符拼接，null 元素按空串 | `@FUN(listJoin,$.tags,/)` |
| `listOp` | `listOp(List,String)` | 列表加工 | `@FUN(listOp,$.tags,DISTINCT)` |
| `listOp` | `listOp(List,String,String)` | 列表加工（带参数） | `@FUN(listOp,$.tags,LIMIT,3)` |

**`listOp` 支持的 op**

| op | 语义 | 返回 |
| --- | --- | --- |
| `DISTINCT`（默认） | 去重，**保持首次出现顺序** | List |
| `SORT` / `SORT_DESC` | 排序（数值按数值比，否则按字符串比） | List |
| `REVERSE` | 反转 | List |
| `LIMIT`（需第 3 个参数） | 取前 N 个 | List |
| `MAX` / `MIN` | 取最大/最小元素 | 单个元素 |

## 7. 自定义规则

### 7.1 注解 + 注册

```java
package com.mycorp.rules;

public class MyBankRules {

    /** 客户侧业务规则：统一社会信用代码等客户数据必须外移出内置规则 */
    @IfmapRule(value = "myCertType", desc = "XX银行证件类型转换",
            example = "@FUN(myCertType,$.certType)")
    public String myCertType(String certType) {
        if ("01".equals(certType)) {
            return "A";
        }
        return "B";
    }

    /** 需要环境信息时，把 RuleContext 声明为第一个参数（模板里不用传） */
    @IfmapRule("tenantPrefix")
    public String tenantPrefix(RuleContext ctx, String value) {
        return ctx.getTenantId() + "-" + value;
    }
}
```

```java
IfmapEngine engine = IfmapEngine.builder()
        .register(new MyBankRules())   // 可多次调用（Spring Boot 3 引 starter 时自动收集，无需手工注册）
        .build();
```

`Builder` 全部选项：

| 方法 | 说明 |
| --- | --- |
| `jsonOps(JsonOps)` | 指定 JSON 实现；不指定则用 SPI 自动发现 |
| `registry(RuleRegistry)` | 传入现成注册表（多个引擎共享规则集） |
| `builtins(boolean)` | 是否注册 18 个内置规则，默认 `true` |
| `register(Object...)` | 追加自定义规则实例 |
| `nullPolicy(NullPolicy)` | 空值策略，默认 `SKIP_FIELD` |

### 7.2 规则方法约束

| 约束 | 说明 |
| --- | --- |
| 可见性 | 必须 `public`（含从父类继承的 public 方法） |
| 注解 | `@IfmapRule` 写在**方法**上；`value` = 规则名（**必填**），另有 `desc` / `example` / `allowNullArgs` / `override` |
| 规则名 | 由 `@IfmapRule("name")` 的 `value` **必填**指定（不写编译不过）。含空格/逗号等非法字符会被拒绝注册 |
| 承载类 | 建议 `public` 具名类（反射要求可访问）；**不要用匿名内部类** |
| 静态方法 | 支持（实例会被忽略） |
| 可变参数 | 支持（`Object...`），此时按实参个数匹配 |
| 返回类型 | 任意；建议 `String`（报文里大多是字符串） |

### 7.3 重载与覆盖

| 场景 | 行为 |
| --- | --- |
| 同名不同参数（重载） | **允许**，按实参类型精确匹配（含装箱类型转换、`String` 形参对 `List` 实参的逐元素映射） |
| 同名同参数（重复签名） | **拒绝**，抛 `IfmapConfigException`（消息里提示可用 `override = true`） |
| 覆盖内置规则 | `@IfmapRule(value = "numRound", override = true)`，**整体替换**该名字下的全部重载 |
| 覆盖后再普通注册同名 | 拒绝（避免半覆盖的混乱状态） |
| 覆盖者重复 | 拒绝（同一名字只能有一个覆盖者） |

```java
public class StrictNumberRules {
    @IfmapRule(value = "numRound", override = true, desc = "本行统一用 HALF_EVEN")
    public String numRound(String value, Integer scale) {
        if (value == null || value.trim().length() == 0) {
            return null;
        }
        return new java.math.BigDecimal(value.trim())
                .setScale(scale == null ? 2 : scale, java.math.RoundingMode.HALF_EVEN)
                .toPlainString();
    }
}
```

### 7.4 校验规则集

```java
engine.getRegistry().getRuleNames();        // 全部规则名（有序）
engine.getRegistry().getDescriptors();      // 全部重载的描述（名字/签名/说明/示例）
engine.getRegistry().contains("numRound");  // 是否存在
```

## 8. 内置规则的设计边界（重要）

内置规则只提供**通用**能力，以下内容**不应**进 core，而应通过 §7 外挂：

| 类别 | 例子 | 归属 |
| --- | --- | --- |
| 银行码值映射 | 各行的票据类型/证件类型/规模代码 | **模板表达式**（`dictVal`）或外挂规则 |
| 客户业务规则 | 硬编码统一社会信用代码、特定企业的特例分支 | 外挂规则模块（如 `ifmap-rules-ecc`） |
| 客户数据 | 具体企业的名称、账号 | 配置/数据，不进代码 |
| 文件路径拼接等环境相关逻辑 | 各家 FTP 路径规则 | 外挂规则 |

> 判据：**规则里出现具体客户/银行的数据或分支，就说明它不该在 core 里。**
