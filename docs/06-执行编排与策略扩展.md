# 06 · 执行编排与策略扩展（W4）

> 面向 `ifmap-core` 的 **编排器（Orchestrator）** 与 **策略 SPI**。
> 读完之后你应该能回答：一次"接口调用"到底按什么顺序发生了什么、我在哪一层插手、配置里写错什么会在启动期（而不是线上）被拦下。

---

## 1. 一次调用发生了什么

```java
IfmapResult result = orchestrator.execute(request, "BIZ_APPLY", "apply");
```

`execute` 内部的实际顺序（**每一格都可以被你替换**）：

| # | 步骤 | 由谁决定 | 可替换点 |
|---|---|---|---|
| 1 | 解析租户 | `TenantResolver` | 上下文 `tenantId` > 请求头 `X-Tenant-Id` > 默认 `-1` |
| 2 | 查配置（含**递归**前置接口 `front_interface_no`） | `ConfigRepository` | 仓储 SPI / 缓存装饰器 |
| 3 | 拓扑排序 + 环检测（`interface_order` 定序） | `InterfaceOrdering` | — |
| 4 | 逐条配置：组包参数（按 (partnerCode, busiNode)） | `FullParamStrategyRegistry` | `FullParamStrategy` |
| 5 | 渲染**请求**模板 | `IfmapEngine` + `RuleRegistry` | `@IfmapRule` |
| 6 | 特殊处理（补字段 / 换报文形态）后**再次渲染** | `SpecialDealStrategyRegistry` | `SpecialDealStrategy`（按 `strategy_name`） |
| 7 | 出网 | `PartnerServiceGateway` | 宿主实现（HTTP/SDK/local stub） |
| 8 | 渲染**响应**模板 → `IfmapResult.data` | `IfmapEngine` | — |
| 9 | 判定成功/失败 | `ResponseJudge`（`result_flag` + `success_value`） | — |
| 10 | 命中逻辑分支 → 执行动作 | `LogicBranchStrategyRegistry` + `ActionRegistry` | `@LogicBranch` / `@IfmapAction` |
| 11 | 落执行日志（脱敏 + 截断） | `ExecutionLogSink` / `LogMasker` | `ifmap.log.*` |

失败即停：`stopOnFailure=true`（默认）时某条配置判定失败就不再执行后续配置，但**已执行日志仍会落库**。

### 前置接口与环检测

`front_interface_no` 指向**另一个 `interface_no`**，所以编排器会**递归**把它拉进来（不是只查一次）。

```text
配置：BIZ_APPLY.front_interface_no = BIZ_TOKEN
执行顺序：[BIZ_TOKEN, BIZ_APPLY]     ← 拓扑排序：前置接口先跑，数据按序合并
```

- 递归深度护栏 `MAX_FRONT_DEPTH = 64`，配置成环或链条过长时抛 `IfmapConfigException`（不会把数据库查穿）。
- 环检测在排序阶段做，异常消息里带**完整环路径**（形如 `循环依赖：A -> B -> A`）。
- 前置接口已执行过则复用（`LinkedHashSet` 去重），不会重复出网。

### 试跑（dry-run）

```java
// 第四个参数 mockResponse 非空时不出网，直接拿它当"资方响应"
IfmapResult r = orchestrator.execute(request, "BIZ_APPLY", "apply", "{\"resultCode\":\"0000\"}");
```

管理端"保存前试跑"就是靠它：**不碰真实资方**，只验证模板 + 判定 + 分支 + 出参映射。

## 2. 公开模型（`cn.cj.ifmap.core.model`）

### IfmapRequest

不可变（`withAttribute` 返回新实例）+ Builder：

```java
IfmapRequest request = IfmapRequest.builder()
        .tenantId("1001")            // 不填则走 TenantResolver
        .operatorId("zhangsan")
        .requestId("REQ-20250101-001")
        .bizId("BIZ-20250101-0001")  // 业务主键，日志里可反查
        .header("X-Channel", "APP")  // 请求头（大小写不敏感）
        .put("orgCode", "12")        // payload：模板渲染的源数据
        .put("acctName", "张三")
        .attribute("workday", true)  // attributes：给条件/规则用的环境信息
        .build();
```

| 方法 | 说明 |
|---|---|
| `of(Map<String,Object>)` | 直接拿一个 Map 当 payload（等价于 `builder().payload(map).build()`） |
| `empty()` | 空请求（只做渲染时用） |
| `getHeader(name)` | 大小写不敏感取头，未命中返回 `null` |
| `getAttribute(key)` | 取 attributes |
| `withAttribute(k,v)` | 返回**新**实例，不改原件 |

### IfmapResult

```java
IfmapResult.success(dataMap);      // 便捷构造
IfmapResult.failure("余额不足");    // 便捷构造
```

| 方法 | 说明 |
|---|---|
| `isSuccess()` | 判定结果 |
| `getData()` | 响应模板渲染出的 Map（无响应模板时为空 Map） |
| `getRawResponse()` | 资方原始响应报文 |
| `getExecutedInterfaces()` | 实际执行过的接口号，**按执行顺序**（断言用） |
| `getMatchedBranch()` | 命中的 `logic_branch_flag`，未命中为 `null` |
| `getElapsedMs()` | 耗时（`ClockProvider` 计时，测试可注入假时钟） |
| `getErrorMessage()` | 失败原因 |

## 3. 三类策略 SPI（对应存量三工厂）

> 共同点：**都是普通接口**。宿主机写一个 `@Component` 实现类即可，starter 自动注册（见 §5），
> **不再有**"按 bean 名反射调方法"的隐式约定。

| 接口 | 注册键 | 注解 | 何时被调用 |
|---|---|---|---|
| `SpecialDealStrategy` | **bean 名**（与 `ifmap_config.strategy_name` 对齐） | 无（靠 bean 名） | 请求渲染后，可改报文或补字段 |
| `FullParamStrategy` | `partner|busi` | `@FullParam(partnerCode=..., busiNode=...)` | 每条配置渲染**前**组装公共参数 |
| `LogicBranchStrategy` | 分支 flag | `@LogicBranch("...")` | 判定后，判断"这条分支算不算命中" |
| `IfmapActionHandler` | 动作 key | `@IfmapAction("...")`（**类级注解**） | 分支命中后执行落地动作 |

```java
@Component
@FullParam(partnerCode = "CMB", busiNode = "apply")
public class CmbApplyFullParam implements FullParamStrategy {
    @Override
    public Map<String, Object> assemble(StrategyContext context) {
        Map<String, Object> full = new LinkedHashMap<>();
        full.put("partnerCode", "CMB");
        full.put("channelCode", "ECC");
        return full;   // 会成为请求模板渲染源的一部分（模板里写 $.partnerCode 即可取到）
    }
}
```

### SpecialDealStrategy：改的是"报文"，不只是"字段"

`apply(StrategyContext)` 的返回值会**合并进渲染参数后重新渲染请求模板**，所以它既能补字段，也能整体换形态：

```java
@Component   // bean 名 = czbApplyStrategy → 配置里 strategy_name 写 czbApplyStrategy
public class CzbApplyStrategy implements SpecialDealStrategy {
    @Override
    public Map<String, Object> apply(StrategyContext context) {
        // 拿到当前报文、模板、配置、RuleContext，随便改
        context.setRequestJson("{\"wrapper\": ...}");
        return Collections.singletonMap("signType", "RSA2");
    }
}
```

- 返回 `null` 或空 Map = 不改。
- `strategy_name` 有值但**没有对应策略** → 默认**抛 `IfmapStrategyException`**（`ifmap.orchestrator.fail-on-missing-strategy=false` 时可降级为 WARN 跳过）。
- 异常消息会列出**所有已注册的 key**，便于直接对照修正（存量"11/38 不一致"就是这么炸的）。

### FullParamStrategy：查找顺序是显式契约

`lookup(partnerCode, busiNode)` 依次尝试，**先精确后通配**：

```text
CMB|apply  →  CMB|*  →  *|apply  →  *|*
```

`contains(partnerCode, busiNode)` / `keys()` 可在保存前校验里用来判断"这家银行到底有没有配组包策略"。

### LogicBranchStrategy vs `logic_branch_value`

分支是否命中，**两条路任一成立即可**（`matches` 里 or 关系）：

1. `logic_branch_flag` 有值且注册了同名 `@LogicBranch` 策略 → 调它的 `match(ctx)`（复杂条件，如"金额 > 100 万且渠道=APP"）；
2. `logic_branch_value` 有值且与判定取到的实际值相等（多值用 `;` 或 `,` 分隔，大小写不敏感）。

都判定为"未命中"时落 WARN 日志，`getMatchedBranch()` 为 `null`；配置写错（flag 与 value 都为空）会额外 WARN 指出 `key_id`。

### 动作（替代 `method_flag` 反射）

```java
@Component
@IfmapAction("submit")            // 注解写在类上（TYPE 级）
public class SubmitAction implements IfmapActionHandler {
    @Override
    public void execute(StrategyContext context) {
        // context.getInterfaceNo() / getBizId() / getMatchedBranch() / getResponseData()
    }
}
```

- 动作 key 取 `method_flag`；`method_flag` 为空时退化为用 `logic_branch_flag`。
- **缺失动作默认快速失败**（`fail-on-missing-action=true`）；置 `false` 时 WARN 跳过。

## 4. StrategyContext（策略能看到什么）

| 方法 | 内容 |
|---|---|
| `getRequest()` | 本次 `IfmapRequest`（租户/业务号/操作人/头/属性） |
| `getConfig()` | 当前 `IfmapConfig`（含 `interfaceNo` / `partnerCode` / 模板原文） |
| `getRuleContext()` | 渲染用的 `RuleContext`（租户、接口号、attributes） |
| `getParams()` | 当前渲染参数（组包 + 特殊处理的结果都在里面） |
| `getRequestJson()` / `setRequestJson(...)` | 出网报文（特殊处理可直接改写） |
| `getResponseJson()` / `getResponseData()` | 资方原始响应 / 已渲染的响应数据 |
| `getMatchedBranch()` | 命中分支 flag |
| `getInterfaceNo()` / `getBizId()` | 便捷取用（空安全） |
| `putParam(k,v)` / `putParams(map)` | 追加渲染参数 |

## 5. Spring Boot 里需要做什么（starter 自动收集）

只要你的策略类是个 Spring bean，**什么都不用配**：

| 你的 bean 实现了 | starter 用它注册到 |
|---|---|
| `SpecialDealStrategy` | `SpecialDealStrategyRegistry`，key = **bean 名** |
| `FullParamStrategy`（带 `@FullParam`） | `FullParamStrategyRegistry` |
| `LogicBranchStrategy`（带 `@LogicBranch`） | `LogicBranchStrategyRegistry` |
| `IfmapActionHandler`（带 `@IfmapAction`） | `ActionRegistry` |
| `IfmapCallbackHandler`（带 `@IfmapCallback`） | `CallbackRegistry`，key = 接口号 |
| 方法带 `@IfmapRule` 的任意 bean | `RuleRegistry`（W3 能力） |

**启动期快速失败**：实现了策略接口但**缺注解**（`@IfmapAction` / `@FullParam` / `@LogicBranch` / `@IfmapCallback`），
启动即抛 `IllegalArgumentException` 并指出 **bean 名 + 类名** —— 不把问题留到线上第一次调用。

注解查找会**沿父类链与接口链**进行（`Annotations.find`），所以被 Spring AOP/CGLIB 代理过的 bean 也能正确识别。

想完全接管某一层？声明同类型 bean 即可（starter 所有 bean 都是 `@ConditionalOnMissingBean`）：

```java
@Bean
IfmapOrchestrator ifmapOrchestrator(IfmapEngine engine, ConfigRepository repository) {
    return IfmapOrchestrator.builder()
            .engine(engine).repository(repository).tenantResolver(new MyTenantResolver())
            .stopOnFailure(false)
            .build();
}
```

### 相关配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| `ifmap.tenant-header` | `X-Tenant-Id` | 取租户的请求头名 |
| `ifmap.default-tenant-id` | `-1` | 都取不到时的兜底租户 |
| `ifmap.orchestrator.stop-on-failure` | `true` | 失败即停 |
| `ifmap.orchestrator.fail-on-missing-strategy` | `true` | `strategy_name` 找不到策略时是否快速失败 |
| `ifmap.orchestrator.fail-on-missing-action` | `true` | 动作未注册时是否快速失败 |
| `ifmap.log.enabled` | `true` | 是否装配执行日志落库 |
| `ifmap.log.truncate-threshold` | `65536` | 单条报文落库最大长度，超出打标 `...truncated` |
| `ifmap.log.mask-fields` | 空（= 内置姓名类字段） | 按**字段名**脱敏的字段 |
| `ifmap.log.exclude-fields` | 空 | 这些字段**整体**替换为 `***` |

> `mask-fields` 留空 = 用内置默认（`acctName` / `accountName` / `certName` / `userName` / `realName` / `legalName` / `legalPerson` / `contactName`）。
> 想**完全关闭**按字段名脱敏，请自定义 `LogMasker` bean（属性留空不代表"关闭"，否则姓名会被原样落库）。

## 6. 脱敏与截断（合规）

`DefaultLogMasker`（core 内置，零依赖）对**要落库的报文**做两件事：

| 形态 | 处理 | 示例 |
|---|---|---|
| `phone` / 手机号 | 中间打星、保留头 3 尾 4 | `13812348888` → `138****8888` |
| 身份证 | 保留头 6 尾 4 | `320102199001011234` → `320102********1234` |
| 银行卡 | 保留头 6 尾 4（13~19 位） | `6222021234567890` → `622202******7890` |
| 姓名字段 | 只留首字 | `张三` → `张*`、`张小三` → `张**` |
| `exclude-fields` | 整体替换 | `idCard` → `***` |
| `null` / 非 JSON | 原样返回（不抛异常） | — |

- 幂等：已经脱敏过的报文再过一遍结果不变（不会越脱越短）。
- 值形态识别**含不加引号的数字**（`"acctNo":6222021234567890` 同样脱敏）；
  短号与金额不动（`{"amount":"1000.00","seq":"123456","count":3}` 原样返回）。
- **嵌套 JSON 字符串内部不脱敏**（`{"sub":"{\"mobile\":\"13812348888\"}"}` 原样返回）——
  避免把已转义的报文改坏。
- 截断在脱敏之后做：超 `truncate-threshold` 的报文尾部替换为 `...truncated`（常量 `Logs.TRUNCATED`）。

```java
LogMasker masker = new DefaultLogMasker();
masker.mask("{\"mobile\":\"13812348888\"}");   // {"mobile":"138****8888"}
```

> 日志落地后还有两件事：**保留期清理**（默认 90 天，分批删除 + 定时任务）与**写日志失败的降级**；
> 连同合规自查清单见 [`docs/08-日志与合规.md`](08-日志与合规.md)。

## 7. 判定（`result_flag` + `success_value`）

```text
result_flag   = $.resultCode         ← 在响应报文里取值的 JsonPath
success_value = 0000                 ← 命中即成功（多值用 , 或 ; 分隔，忽略大小写）
```

| 场景 | 结果 |
|---|---|
| `result_flag` 为空 | **成功**（没有约定字段就认为资方受理了） |
| `success_value` 为空 | 取到的值**非空即成功** |
| 取到的值 ∈ 期望值（忽略大小写、去空格、`true`/`1` 归一化） | 成功 |
| 取不到值 / 不在期望值里 | 失败（`getErrorMessage()` 说明实际值） |
| 响应不是合法 JSON | 失败（**抛异常会炸掉整条链路，这里不抛**） |

> **与存量的差异**：存量 `success_value` 支持三种写法 —— 单值 `a`、多值 `a,b,c`（英文逗号）、
> **取反 `!a`**（不等于 `a` 即成功）。ifmap 支持前两种（`,` 或 `;` 分隔，忽略大小写）与
> 「`success_value` 为空时非空即成功」，但**不支持 `!` 取反**：存量里写了 `!` 的配置必须先改成
> 等价写法再迁移（见 [`docs/10`](10-迁移指南.md) §7 第 12 条）。比较是**按分隔符切分后逐个相等比较**
> （不是正则匹配），所以 `0000|S` 这种写法在这里是**一个**候选值，不是两个。

## 8. 契约自检（部署前跑一次）

```java
ContractReport report = new ContractValidator(engine).validate(repository.queryConfigs("1001", "BIZ_APPLY", "apply"));
if (!report.isClean()) {
    log.error("ifmap 配置契约有问题：\n{}", report.toMarkdown());
}
```

检查项：

| 检查 | 拦截的线上事故 |
|---|---|
| 模板是合法 JSON（请求 + 响应两侧） | 手改模板漏了个引号 |
| `@FUN(name,...)` 的 `name` 已注册 | `farmatDate` 这类拼写错误 |
| `@FUN` 参数个数/类型能匹配到某个重载 | 少传参数的静默 null |

`report.toMarkdown()` 可直接贴 CI 产物或工单；零违规时输出"零违规"字样（测试里就是这么断言的）。

## 9. 异常体系

| 异常 | 抛出时机 | 处置建议 |
|---|---|---|
| `IfmapConfigException` | 配置非法/缺失（含前置链成环、深度超限、必填列为空） | 直接暴露给调用方修配置 |
| `IfmapStrategyException` | 策略/动作缺失且走的是"快速失败" | 启动期就该发现，运行期即报警 |
| `IfmapRemoteException` | 宿主机 `PartnerServiceGateway` 出网失败 | 由宿主决定重试/降级（引擎不重试） |
| `StartupValidationException` | `engine.validateTemplate(...)` 模板校验失败 | 部署前拦下 |

## 10. 无 Spring 环境（纯 Java）

```java
IfmapOrchestrator orchestrator = IfmapOrchestrator.builder()
        .engine(IfmapEngine.createDefault())
        .repository(new MyRepository())            // ConfigRepository SPI
        .tenantResolver(new HeaderTenantResolver())
        .callbacks(new CallbackRegistry())
        .build();                                  // engine/repository/tenantResolver 必填
```

未配置的组件会退化为安全默认值（`jsonOps` 取 `engine.getJsonOps()`、`clock` 取 `SystemClockProvider.INSTANCE`、
`conditionResolver` 取 `AttributeConditionValueResolver`、缓存/策略注册表为空注册表）。
**没有 `PartnerServiceGateway` 时不会出网，只做本地渲染**（日志里 WARN 提示，等同于 dry-run）。
